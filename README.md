# colorlab. — Astro rebuild

A from-scratch clone of [www.colorlab.ca](https://www.colorlab.ca) (the current live site, built on Framer), rebuilt with **Astro + Tailwind CSS + Framer Motion**, with SEO/AI-search optimization and performance tuning applied. Builds to pure static HTML/CSS/JS — no server runtime, no database, no subscription, deployable anywhere.

## Deployment target: this repo serves `colorlab.ca` (apex)

This repo is `colorlabIT.github.io` — GitHub's special naming convention for a user/org's primary Pages site — and its custom domain (`public/CNAME`) is set to the **apex** `colorlab.ca`, not `www`. It previously held an old, unrelated static site (plain HTML, light theme, different copy) left over from before the live site moved to Framer; that content has been replaced with this rebuild via a fresh commit (full history preserved — see earlier commits in this repo for the old version).

`www.colorlab.ca` is still on Framer as of this writing. GitHub Pages reserves `www.<domain>` automatically once the apex is claimed in the same account, so `www` can't be pointed at a *different* repo without first removing the apex claim here. Decide separately whether you want `www` to also move to this rebuild (in which case redirect it here) or stay on Framer (in which case redirect this apex to `www`, or leave both as independent sites).

## Stack

- **Astro** (static output, zero client JS by default) for the page shell and routing
- **Tailwind CSS v4** (via `@tailwindcss/vite`) for styling — utility classes only, no class names borrowed from the original Framer export
- **React + Framer Motion** for the interactive/animated pieces: hero fade-in, the count-up stat counters, scroll-reveal on service cards and gallery items. These are Astro "islands" — only the components that need JS ship any, everything else is static HTML

## What changed from the live site

- **Content and layout**: matched section-for-section against the live site (hero, intro/stats band, 4 services, 9-photo project gallery, contact, footer) by inspecting the rendered page directly, not just the raw HTML, since Framer sites animate content (e.g. the stat counters start at 0 and count up on scroll — the real target values 50+/2000+/100+ were captured by triggering that animation live).
- **All assets localized**: every image and font that lived on `framerusercontent.com` / `fonts.gstatic.com` was downloaded and is now served from `public/images/` and `public/fonts/`. Nothing loads from Framer's CDN.
- **Tracking removed**: the live site loads `events.framer.com/script?v=2`, Framer's own analytics beacon. This rebuild has no analytics of any kind. Add your own (e.g. a privacy-respecting, self-hosted option) if you want traffic data.
- **Images optimized**: re-compressed to reasonable quality (82/80 JPEG quality) with `.webp` siblings served via `<picture>`, and lazy-loaded below the fold.
- **Fonts self-hosted**: EB Garamond (serif headings) and Geist (sans body text) were on Google Fonts; both are now local `.woff2` files, Latin subset only (the only subset this site's English content needs).
- **SEO**: canonical tag, Open Graph + Twitter Card tags, `HomeAndConstructionBusiness` + `WebSite` JSON-LD (address, phone, email, and an `OfferCatalog` listing all four services), descriptive `alt` text on every image, clean H1→H2→H3 heading order.
- **AI search**: `llms.txt` at the root summarizing the business for AI crawlers/answer engines.
- **No fabricated data**: the JSON-LD intentionally omits a postal code, social profile links (`sameAs`), and a founding date — none of these are published on the live site, so none were invented. (The "50+ Years of Expertise" stat reads as combined team experience, not a literal founding date, so it wasn't used as one.)

## Building for production

```bash
npm run build
```

Output lands in `dist/`. Copy that folder's contents to any static host.

### Apache

Copy everything in `dist/` (including the hidden `.htaccess`) to your document root. Make sure `mod_deflate`, `mod_expires`, and `mod_headers` are enabled, and `AllowOverride All` is set so `.htaccess` is honored.

### Nginx

Copy `dist/`'s contents (Nginx ignores `.htaccess`) to your web root, then merge `nginx.conf.example`'s `location` blocks into your real server block and reload Nginx.

### Netlify / Cloudflare Pages / GitHub Pages

All three serve static files directly:

- **Netlify**: `netlify deploy --dir=dist --prod`, or drag-and-drop `dist/` onto the dashboard.
- **Cloudflare Pages**: connect the repo (build command `npm run build`, output directory `dist`) or upload `dist/` directly.
- **GitHub Pages**: push `dist/`'s contents to a `gh-pages` branch (or `/docs` on `main`) and enable Pages — this is how the *old* apex-domain site is currently hosted, so if you go this route for the real site, make sure the DNS issue above gets sorted so the right deployment answers the right hostname.
